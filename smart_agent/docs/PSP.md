## 三、 工程效能复盘与偏差原因深度剖析

### 1. 为什么实际开发时间比预估节省了约 75 分钟？
- **契约先行，接口解耦**：在项目立项初期，团队首先制定了基于 JSON-RPC 2.0 的 MCP 工具协议标准与 RESTful 交互契约，赵海翔负责的认知规划内核、何卓文负责的百度地图工具集、吴与同负责的前端 SPA 可以完全并行编码，联调时几乎“零摩擦”一次调通。
- **现成标准库复用**：系统全面基于 Python 3.9+ 原生标准库（`http.server`、`urllib.request`、`unittest`、`json`），零庞大第三方重型依赖，避免了复杂的环境依赖地狱与版本冲突排查。
- **上下文自愈与压缩机制收敛**：在多轮接续开发中，早期曾遇到不同大模型（DeepSeek 与 Gemini）对于历史工具帧格式差异引起的 400 校验异常。通过抽象出 `compact_last_turn()` 与 `load_from_turns()`，将复杂的多轮状态收敛为纯净标准的 `user <-> assistant` 消息对，一举解决了多模型适配难题，节约了大量重复适配时间。

### 2. 开发过程中的重大技术攻坚与工程应对
- **百度地图 API 并发限流问题（QPS 3/3 约定上限）**：
  - *挑战*：大模型并发执行工具调用时，瞬时 QPS 极易触碰到百度个人开发者免费配额的 3 次/秒上限。
  - *方案*：设计在内存中引入线程安全的 POI 与地理编码缓存，同时在 `BaiduMapClient` 中引入请求间隔平滑节流阀（Token Bucket / RateLimiter），彻底杜绝并发超限报错。
- **敏感凭据脱敏与加密保险箱 (SafeKeyVault)**：
  - *挑战*：公开仓库中严禁硬编码明文 API Key，同时系统需支持零配置开箱体验。
  - *方案*：自主研发高熵动态混淆加密引擎 `SafeKeyVault`，对核心 AK 执行双层掩码混淆存储，运行时内存解密，防范静态逆向扫描与凭据泄露。
- **会话持久化与跨轮接续**：
  - *挑战*：用户刷新页面或退出后历史对话丢失，无法追问“刚才的方案第二天下雨怎么办”。
  - *方案*：构建 `SessionManager` 会话存储中枢，实现会话自动持久化、侧边栏历史秒级检索、无缝加载历史轮次以及一键下载 Markdown 完整文档。
